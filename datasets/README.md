## 1. Built-in simulated data (default, no download)

The demo and the default models use data generated by `ml/maintenix_ml/simulator.py`. It is synthetic. Every row carries `data_source = "simulated"` and the UI labels such equipment "Simulated".

| Equipment type | Mode | Sensors | RUL |
|---|---|---|---|
| `centrifugal_pump` | runs to failure (bearing wear) | temperature, vibration, pressure, rotational_speed, power | yes |
| `electric_motor` | runs to failure (insulation and bearing wear) | temperature, vibration, rotational_speed, current | yes |
| `air_compressor` | intermittent faults that end in a trip, then repair | temperature, vibration, pressure, power | **no** (no run to failure trajectory) |

Generate a fleet yourself:

```python
from maintenix_ml.simulator import generate_fleet
df = generate_fleet("centrifugal_pump", n_units=60, seed=42)  # deterministic
```

Ground truth columns (`gt_*`) exist only because the data is synthetic. They are used for labels and evaluation, never as model inputs.

## 2. NASA C-MAPSS (optional, for RUL research)

The Commercial Modular Aero-Propulsion System Simulation turbofan degradation dataset (Saxena et al., 2008) is the standard public benchmark for RUL.

**It is not included and was not available while this repository was built** (the build environment could not reach the NASA download hosts). No C-MAPSS metrics are claimed anywhere in this project.

### Acquire

1. Download "Turbofan Engine Degradation Simulation Data Set" from the NASA Prognostics Center of Excellence data repository: <https://www.nasa.gov/intelligent-systems-division/discovery-and-systems-health/pcoe/pcoe-data-set-repository/>
2. Extract `train_FD001.txt`, `test_FD001.txt` and `RUL_FD001.txt` into `datasets/raw/cmapss/`.

### Schema (FD001)

Whitespace separated, no header, 26 columns: `unit, cycle, op_setting_1..3, s1..s21`. Training units run to failure; test units stop early and `RUL_FD001.txt` gives the true remaining cycles of each test unit's last row.

### Preprocessing (`ml/maintenix_ml/adapters/cmapss.py`)

* RUL target: `max_cycle(unit) - cycle`, clipped at 125 cycles (piecewise linear target).
* Constant sensors in FD001 (s1, s5, s6, s10, s16, s18, s19) are dropped.
* One cycle is stored as one hour of synthetic timestamp so the common pipeline applies. Read RUL values as cycles.
* Splits are by engine, never by row.
* Test engines with fewer cycles than the 48 reading feature window are skipped (reported, not padded).

### Train and evaluate

```bash
python -m maintenix_ml.train cmapss --data-dir datasets/raw/cmapss --subset FD001
```

The run prints validation and test metrics plus RMSE, MAE and the asymmetric NASA score on the official test set.

### Licence and attribution

C-MAPSS is published by NASA as public domain US Government data. Cite: A. Saxena, K. Goebel, D. Simon, N. Eklund, "Damage Propagation Modeling for Aircraft Engine Run-to-Failure Simulation", PHM 2008.

## 3. Your own CSV data

Upload through **Sensor monitoring → Import CSV readings** or `POST /api/v1/sensors/readings/upload`. See `samples/readings_example.csv`. Columns: `equipment_code, timestamp, operating_mode, operating_hours` and the sensor names of that equipment's type. Validation rejects missing or non numeric values, out of range readings, unknown columns, unparseable or future timestamps and duplicates, and warns about irregular sampling intervals.
